04 / ENDPOINTS

Endpoint onboarding

A safe, repeatable outline for enrolling authorized Linux and Windows lab systems.

Use version-matched instructions

Generate agent commands from the dashboard or official documentation for the actual manager version. Never put private manager addresses or enrollment secrets in public docs.

LINUX

Linux agent workflow

  1. Confirm authorization and a route to the manager.
  2. Install the agent using official distribution-specific instructions.
  3. Configure the manager address locally.
  4. Enable and start the agent service.
  5. Confirm the agent appears active in the dashboard.
sudo systemctl status wazuh-agent
sudo systemctl enable --now wazuh-agent
sudo journalctl -u wazuh-agent --no-pager -n 100
WINDOWS

Windows agent workflow

  1. Select Windows in the agent deployment workflow.
  2. Follow generated installation and enrollment instructions.
  3. Run required steps in an elevated PowerShell session.
  4. Check service state and agent logs.
  5. Confirm the agent is active and events are arriving.
Get-Service WazuhSvc

Network requirements

Agent communication commonly uses port 1514; enrollment commonly uses TCP 1515. Protocols and ports depend on configuration and release. Verify the real setup and allow only required traffic between trusted lab systems.

Definition of done

  • Agent service is running.
  • Agent is registered and active in the manager/dashboard.
  • Relevant event sources are enabled.
  • A harmless test event appears in the real dashboard.
  • Evidence is sanitized before publication.
