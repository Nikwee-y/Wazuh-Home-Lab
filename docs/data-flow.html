How an event flows through a SOC

A harmless, fictional example from endpoint event to analyst decision. Actual results depend on configured data sources, rules, and integrations.

Illustrative scenario—not live telemetry

This example uses fictional repeated failed logins. It does not connect to Wazuh or claim that an alert occurred on your lab.

EVENT PIPELINE

From endpoint to investigation

Replay on homepage ↗
  1. Endpoint event

    A test endpoint records repeated failed logins in a short period. The event source must be configured to collect those records.

  2. Wazuh Agent

    The agent collects configured logs and forwards events to the manager over the allowed network path.

  3. Wazuh Manager

    Decoders parse event fields and rules evaluate whether the event matches a detection condition or threshold.

  4. Wazuh Indexer

    Generated alert data is indexed for later searching and correlation.

  5. Wazuh Dashboard

    An analyst reviews the alert, validates context, scopes related activity, and chooses an authorized next action.

  6. Response / case management

    Response actions should follow an approved playbook. TheHive and automation are future plans, not active integrations in this baseline.

What is required in the real lab?

  • Docker and required Wazuh services are running and healthy.
  • The endpoint has a registered, connected agent.
  • The relevant event source is enabled and producing data.
  • The manager has applicable decoders, rules, and thresholds.
  • The indexer and dashboard can access alert data.
  • The analyst verifies the alert in the actual dashboard, not in the site animation.
