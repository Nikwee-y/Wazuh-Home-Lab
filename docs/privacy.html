08 / PUBLICATION SAFETY

Privacy & hardening

Publish the method and lessons—not private infrastructure details.

Never publish secrets

Do not commit passwords, access tokens, API keys, agent enrollment secrets, private keys, certificates, raw logs, or private runtime data.

Use placeholders

Private informationPublic-safe replacement
Manager or VPN address<WAZUH_MANAGER_PRIVATE_ADDRESS>
Dashboard URL<PRIVATE_DASHBOARD_URL>
Username<LOCAL_USERNAME>
Endpoint name<LAB_ENDPOINT>
Credential/tokenOmit it entirely.

Pre-commit review

git status --short
git diff
git diff --cached
git log --all --stat
  • Inspect terminal output, screenshots, configs, and issue text.
  • Exclude .env files, local inventories, data directories, and raw telemetry.
  • Scan for secrets before pushing.
  • Deleting a secret in a new commit does not erase its old Git history.
  • Rotate any secret that was exposed, even if later deleted.

Network hardening baseline

  • Avoid router port forwarding for the SOC stack.
  • Restrict dashboard, indexer, and manager interfaces to trusted paths.
  • Use host firewalls and allow only required ports.
  • Patch host, Docker, Wazuh, and agents.
  • Back up persistent data securely and test restoration.
  • Collect only authorized lab telemetry.
